# Як ми працюємо

Ці домовленості спільні для всіх, хто розвиває систему оповіщення. Вони відтворюють звичайний процес
команди розробників: задача на дошці, окрема гілка, зелені тести, pull request, перегляд коду, злиття.

## Один репозиторій для всієї команди

Уся група працює в одному репозиторії, https://github.com/trpz2026/alerting, так само як команда
розробників працює з кодом одного продукту. Клонуйте його один раз:

```bash
git clone https://github.com/trpz2026/alerting.git
cd alerting
npm install    # один раз: встановлює Vitest
npm test       # запускає тести і перезапускає їх після кожного збереження файлу
```

Гілка `main` спільна, і в ній усі тести завжди зелені. Ніхто не робить комітів безпосередньо в `main`:
кожна зміна потрапляє туди через pull request, який переглянула інша людина. Тому система зростає
поступово, і кожна злита задача стає частиною коду, на якому працюють усі.

## Дошка задач

Задачі лежать на дошці Trello курсу. Кожна задача описує, навіщо вона системі, що потрібно зробити і за
якими критеріями її приймають; мітка «Заняття N» показує, до якого заняття задача належить. Списки
дошки показують стан задачі:

| Список | Що означає |
|---|---|
| Заплановано (To Do) | задачі, готові до роботи |
| У роботі (In Progress) | хтось працює над задачею; на картці видно, хто саме |
| На перевірці (Review) | відкрито pull request, задача чекає перегляду |
| Готово (Done) | pull request злито в `main` |

Беручи задачу, додайте себе до її учасників і перенесіть її до списку «У роботі». Одночасно у вас у
роботі одна задача: наступну беруть тоді, коли попередня на перевірці або готова.

## Гілки

Над кожною задачею працюють в окремій гілці від свіжого `main`. Назву гілки вказано на картці; вона
починається з номера задачі, наприклад `feature/05-status` для картки 5:

```bash
git switch main
git pull
git switch -c feature/05-status
```

Якщо ту саму вправу виконує вся група, наприклад на занятті, додайте до назви гілки своє ім'я користувача
GitHub, щоб гілки не збігалися: `feature/leap-year-<ваше-імʼя>`.

## Тести

Задача буває двох видів.

- **Тести задано.** Критерії приймання записані тестами, які лежать у теці `cards/`. На початку роботи
  перенесіть файл своєї задачі до `tests/`, наприклад `git mv cards/05-status.spec.js tests/`.
- **Тести пишете ви** (із заняття 5). Картка дає специфікацію в коментарі над функцією і один заданий
  тест. З кожного речення специфікації ви робите тест, бачите його червоним і лише потім пишете код, з
  яким він проходить.

В обох випадках тести, які вже є в `tests/`, не змінюються: якщо тест червоний, змінюється код.

## Готово означає

- усі тести зелені на вашому комп'ютері (`npm test`) і на GitHub: біля останнього коміту гілки стоїть
  зелена позначка ✓ перевірки «Тести»;
- код зрозумілий: ви переглянули його після того, як тести стали зеленими;
- відкрито pull request у `main`, і його опис заповнено за шаблоном;
- на коментарі перегляду дано відповідь: новими комітами в ту саму гілку або відповіддю в обговоренні;
- pull request злито в `main`, а задача на дошці перенесена до списку «Готово».

## Pull request

Надішліть гілку на GitHub (`git push -u origin feature/05-status`) і відкрийте pull request у `main`.
Назва pull request повторює назву задачі, наприклад «Картка 5: стан оповіщення». Посилання на pull
request додайте до задачі в Trello, а посилання на задачу вкажіть в описі pull request, щоб від кожного
можна було перейти до іншого. Після цього перенесіть задачу до списку «На перевірці».

Pull request переглядає інша людина: сусід або викладач. Коли на коментарі дано відповідь і перегляд
схвалено, автор зливає pull request у `main` і переносить задачу до списку «Готово».

## Перевірка на GitHub

Після кожного `git push` GitHub сам запускає всі тести на чистому комп'ютері, так само як `npm test`
(файл `.github/workflows/tests.yml`). Результат видно біля коміту, у списку гілок і внизу pull request:
жовта позначка ● — тести ще виконуються, зелена ✓ — усі пройшли, червона ✗ — якийсь тест не пройшов.
Натисніть **Details** біля позначки, щоб побачити, який саме, так само як у терміналі.

Зелена позначка важлива тим, що вона не залежить від вашого комп'ютера: тести пройшли на коді, який
лежить на GitHub, а не на файлах, які ви, можливо, забули додати до коміту.

## Якщо `main` змінився, доки ви працювали

Інші тим часом зливають свої задачі, і `main` іде вперед. Перед тим як відкрити pull request, візьміть
ці зміни у свою гілку:

```bash
git switch main
git pull
git switch feature/05-status
git merge main
npm test
```

Якщо Git повідомляє про конфлікт, він позначає в файлі обидві версії рядків, вашу і з `main`. Залиште
правильний варіант, приберіть позначки `<<<<<<<`, `=======`, `>>>>>>>`, переконайтеся, що тести зелені, і
зробіть коміт.

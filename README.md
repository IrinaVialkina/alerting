# Система оповіщення

Це система оповіщення, яку ми розвиваємо на практичних заняттях. Оператор створює оповіщення, система
показує його на екрані, рахує термінові, перевіряє, чи можна його надіслати. Кожне практичне заняття
додає до неї нові можливості, і кожну з них перевіряють автоматичні тести.

Уся група працює в цьому репозиторії: кожна задача робиться в окремій гілці й потрапляє до `main` через
pull request. Як саме, описано в `CONTRIBUTING.md`.

## Як запустити

Потрібні Node.js (версія 22 або новіша) і Git.

```bash
git clone https://github.com/trpz2026/alerting.git
cd alerting
npm install    # один раз: встановлює Vitest
npm test       # запускає тести і перезапускає їх після кожного збереження файлу
```

Щоб зупинити тести, натисніть `q` або `Ctrl+C`.

## Що де лежить

| Файл | Що в ньому |
|---|---|
| `src/` | код системи: кожен модуль в окремому файлі |
| `src/alerts.js` | оповіщення: створення, вигляд на екрані, термінові (заняття 3) |
| `src/time.js` | робота з датами (заняття 4 і 5) |
| `tests/` | тести: кожен файл перевіряє один модуль; `npm test` запускає всі |
| `cards/` | тести карток заняття 3: файл своєї картки переносять до `tests/` |
| `CONTRIBUTING.md` | як ми працюємо: один репозиторій, дошка задач, гілки, тести, що означає «готово», pull request |
| `index.html`, `runner.js` | тести заняття 3 і його карток у браузері, без Node: сторінку відкривають через будь-який вебсервер |

## Правила роботи

1. **Тести не змінюються.** Тест є специфікацією: він записує, що функція обіцяє робити. Якщо тест
   червоний, змінюється код у `src/`, а не тест.
2. **Червоне → зелене → рефакторинг.** Спочатку тест червоний. Далі пишемо найпростіший код, з яким він
   стає зеленим. Потім покращуємо код, а тести тим часом стежать, щоб поведінка не змінилася.
3. **Коміт після кожного зеленого кроку**, з повідомленням, яке описує, що саме зроблено.
4. **У `main` — лише через pull request.** `main` завжди зелений; задача потрапляє туди після перегляду і
   зеленої перевірки «Тести» на GitHub.
